# 代码注释规范（本项目）

> **每个函数方法、定义的 ref 等都要写好注释。**  
> 注释写给人看：用途、单位、边界；禁止复述语法或无信息废话。

本 skill 在本仓库写/改源码时**必须遵守**；与「人类可读」一致，冲突时两者同时满足。

---

## 1. 必须注释的对象

| 对象 | 要求 |
|------|------|
| `function` / `async function` / 方法 | 函数上方 `/** … */`：做什么、关键副作用 |
| `ref(...)` / `reactive(...)` / `computed(...)` | 定义旁注释：含义、单位、取值范围或默认含义 |
| 模块级 `let` / 可变状态 | 用途与谁读写、何时清零 |
| `type` / `interface` / 导出类型 | 业务含义；字段若非自明则补一句 |
| 有业务含义的常量 | 单位、为何取该值（如柱宽下限、速度基准） |
| 导出的 barrel（如 `algorithms/index.ts`） | 文件头说明职责；每条导出可简短标注 |
| CSS 变量（`:root` 色号、圆角、间距等） | 每个变量上一行注释：用在哪（背景 / 柱子 / 按钮态等） |

**可不注释**：一眼明白的循环下标 `i`/`j`、空函数体占位、纯转发且导出名已自明的一行 re-export（仍建议在 barrel 上保留简短标注）。

---

## 2. 注释写法

- 优先 JSDoc / 块注释：`/** 说明 */`，写在声明**正上方**。
- 写：**用途、单位、边界、为何这样**；不写「定义一个变量」「给 x 赋值」。
- 中文注释，与本项目文档语言一致。
- Vue SFC：`script` 内按上表注释；`template` 不堆业务注释。

```ts
/** 用户输入的柱子数量；合法范围 2～500，默认 200 */
const countInput = ref(200)

/**
 * 按当前速度逐步播放排序步骤。
 * 进行中改速度会马上生效；abort / playToken 变化则中断本轮。
 */
async function runSort(name: SortName) {
  // ...
}
```
